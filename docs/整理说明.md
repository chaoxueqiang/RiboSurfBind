# 代码组织与发布说明

本仓库保留论文所需代码、冻结输入、RiboSurfBind 检查点及结果。
面向使用者的安装、训练、评估和预测命令见 [README](../README.md)。

## 组织方式

- `train.py`、`evaluate.py`、`predict.py` 为三个主要用户入口。
- `models/` 实现核苷酸关系分支、分子表面分支及融合，不执行历史第三分支。
- `configs/` 明确记录训练配置、协议、五项消融、三项灵敏度分析和案例设置。
- `data/processed/` 提供六个自包含数据包；`data/splits/` 保存有序划分。
- `data/raw/` 保存可用原始结构、标注及来源，不是冻结特征训练的运行依赖。
- `checkpoints/` 收录55组模型配置，对应53个物理权重文件；重复资产使用仓库内相对软链接。
- `results/` 保留论文指标、可用逐次结果和图件来源；新输出与冻结资产分开。
- 主训练、ERNIE 特征提取和 PyMesh 使用分离环境；PyMOL 为可选可视化环境。

模型兼容层、辅助头、参数初始化顺序及确定性控制保留，不为外观精简而删除。
标签、划分、有效核苷酸、坐标、冻结特征及已归档权重不因文档整理改变。
完整 epoch 边界恢复需要新训练保存的 `resume.pt`，不能仅凭旧 `best_model.pt` 恢复优化器轨迹。

## 当前发布方式

代码、冻结基准数据、RiboSurfBind 训练权重及论文结果放在同一 GitHub 仓库。
`hariboss.pt` 与 `hariboss_tr60.pt` 使用 Git LFS；其余文件按仓库现有规则管理。
原始迁移备份和后续新运行输出不作为论文冻结资产发布。

MSMS 程序和 ERNIE-RNA 预训练权重未打包，需按照
[外部资产说明](EXTERNAL_ASSETS.md) 从官方来源获取。
现有冻结特征的训练、评估及快速示例不需要这两个外部预处理资产。

独立发布仓库从当前工作树导出并新建 Git 历史，不携带实验仓库的旧提交。
不要把实验仓库的旧 `.git` 目录合并进发布仓库；旧历史可能仍保存已排除的外部资产。
